Operation ID: Reports_Reprocess.

Authentication: API key in the header (ApiKeyAuth) or API key in the header (DevID).

Parameters

Parameter In Type Required Description
X-Terra-Version header string (date) No The lab-reports API version to serve this request in, as a YYYY-MM-DD date: the newest version on or before it, or 2026-03-24 for an earlier date. Defaults to the environment's pinned version, else the latest. A malformed or future date is a 400 with code invalid_api_version.
session_id path string Yes The session's snowflake ID.
legacy_format query boolean No Deliver the re-run in the pre-v6 webhook shape. Only needed for a session uploaded on the pre-v6 surface before the upload's shape was recorded with the session; otherwise the recorded shape is used.

Property Type Required Description
collection_date string No Date the sample was collected or the scan was taken (YYYY-MM-DD); omitted if not extracted.
collection_time string No Time the sample was collected or the scan was taken (HH:MM, 24-hour); omitted if not extracted.
current_status string Yes Current status as a clean lowercase string (open enum, handle unknown values gracefully). In flight: processing, processed, standardizing, standardized, sending, and retry_scheduled (waiting to retry after a temporary model-provider error; the report is still being worked on). Terminal: sent, partially_sent (delivered to some destinations), delivery_failed (processed and results available, but no destination accepted the delivery), failed (see error), cancelled, deleted.
error object No Why the report failed: the same object the lab_report.failed webhook carries. Present only while current_status is failed.
error.code string Yes Machine-readable failure code. An open set: handle codes you do not recognise like internal. unsupported_report_type: the file is not a lab report or DXA scan (see document_class). file_unreadable: the file could not be read, for example a blurry or cropped photo, or an image that does not decode; ask the user for a clearer one. file_too_large: the files together exceed what one report can be read from; upload fewer or smaller files. no_results_found: the report was readable but has no results in it. extraction_failed: the results could not be extracted from the file. standardization_failed: the extracted results could not be standardized. internal: a fault on our side.
error.document_class string No For unsupported_report_type only: what the file was judged to be instead of a lab report or scan. other_medical (another medical document, for example a DNA test or an imaging report) or non_medical. An open set.
error.message string Yes Human-readable explanation. Not stable; branch on code.
error.retriable boolean Yes Whether POST …/reprocess may succeed with no change to the input. False means the input must change first: upload a different file.

"lab" for a clinical lab report, "dexa" for a DXA body-composition or bone-density scan, "unspecified" while the report is still being classified. Switch on this before reading results: dexa results are scoped by biomarker.region, lab results by biomarker.specimen.
results array of object No The layered biomarker results. Populated on retrieve, not on list.
results[].biomarker object Yes The normalized identity layer.
results[].biomarker.display_name string No
results[].biomarker.key string or null Yes Canonical biomarker slug, or null when unmatched, the sole no-match signal. Do not key off loinc_code, which can be null on a match.
results[].biomarker.loinc_code string No LOINC code; omitted when the matched biomarker has no LOINC mapping. On a site-scoped (DXA) result the code identifies the (measure, site) pair rather than the measure alone, because LOINC's DXA terms are pre-coordinated, the site is baked into the term. Read it off each result; do not cache it against biomarker.key. Coverage is partial on scans: per-site body-fat percentage and the mass/lean/BMC measures have no LOINC term and omit the field.
results[].biomarker.panel_id integer No References panels[].id on the enclosing session.
results[].biomarker.panel_key string No
results[].biomarker.region enum: head, arms, arm_left, arm_right, legs, leg_left, ... No Canonical anatomical site key for site-scoped (DXA) reports, drawn from a closed vocabulary of ~70 members (arms, arm_left, trunk, android, gynoid, vat, l1_l4, spine_lumbar, femur_neck_left, forearm_total_right, ...). Treated as an open enum on the wire so new sites do not break existing consumers; the full list is published in the Lab Reports documentation. Together with biomarker.key it forms the identity of a scan result, the same measure appears once per site, so key alone is not unique. Omitted for lab results, which are scoped by specimen instead.
